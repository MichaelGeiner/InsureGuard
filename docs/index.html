How the model was built

  • Features in SQL: PostgreSQL window functions compute 7/30-day spend baselines, 1h/24h velocity, haversine travel speed and device age, using only each customer's past.
  • Two models, one score: Isolation Forest (unsupervised) catches anything unusual; XGBoost (supervised) learns known fraud. Blended 20/80 into a 0 to 100 risk score.
  • Honest evaluation: out-of-time split, so the model is graded only on months it never saw. A first version scored a suspicious perfect 1.0 ROC-AUC, which exposed overly clean synthetic data; the generator was rebuilt with realistic noise.
  • Class imbalance: 1.2% fraud handled with class weighting rather than SMOTE, so no synthetic training rows with impossible combinations.
  • Known limitation: friendly fraud (customers disputing their own purchases) leaves no behavioral trace and is caught 0% of the time; that belongs to chargeback investigation, not transaction scoring.
